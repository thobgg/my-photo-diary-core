My Photo Diary · Entwickler-Handbuch · 3.0My Photo Diary · Developer handbook · 3.0

Ein Foto-Tagebuch auf der eigenen NAS — und wie es gebaut ist.

Dieses Handbuch beschreibt MPD aus Entwicklersicht: Architektur, Bereiche, Datenmodell und Betrieb. Es folgt dem Code, nicht dem Prospekt.

MPD macht aus Foto-Ordnern Tagebücher — Fotos, Texte, Karten, Touren, Ton und Dokumente in einer Reihenfolge, die ein Mensch festlegt. Es läuft in einem Docker-Container auf einer Synology-NAS oder jedem Linux-Rechner mit Docker. Python/FastAPI im Backend, reines HTML/CSS/JavaScript im Frontend, kein Build-Schritt.

MPD gibt es als quelloffenen Kern (AGPL-3.0) und mit den Modulen MPD Plus (Suche, Stats, Tours, Trails). Dieses Handbuch beschreibt den Kern; wo ein Plus-Modul ins Spiel kommt, steht es dabei.

A photo diary on your own NAS — and how it is built.

This handbook describes MPD from a developer's angle: architecture, areas, data model and operations. It follows the code, not the brochure.

MPD turns photo folders into diaries — photos, text, maps, tours, audio and documents in an order a person chooses. It runs in one Docker container on a Synology NAS or any Linux machine with Docker. Python/FastAPI in the backend, plain HTML/CSS/JavaScript in the frontend, no build step.

MPD comes as an open-source core (AGPL-3.0) and with the MPD Plus modules (search, stats, tours, trails). This handbook describes the core; where a Plus module comes into play, it says so.

Stack: Python 3.11 · FastAPI · Vanilla JS · SQLite · Docker Auth: Argon2id · 30 Tage30 days Format: PDX 1.5 (album.json)

Drei Versprechen, die alles bestimmen

Wer sie kennt, versteht, warum manche Funktionen bewusst fehlen.

stays yours

Deine Fotos bleiben deine.

Keine Cloud, kein Konto bei Dritten. Ein Album ist ein Ordner mit einer album.json im offenen PDX-Format. Wer MPD morgen löscht, behält Fotos und lesbare Alben.

share by giving

Teilen heißt geben.

Zwei Wege, beide ohne Feed: ein Freigabelink vom Server (Empfänger sehen ein Album zum Ansehen — keine Likes, keine Kommentare, kein Zähler) und das gewöhnliche Weitergeben aus der App über das Android-Teilen-Menü.

locked = mine

Privates bleibt privat.

locked-Elemente filtert der Server beim Teilen heraus, bevor etwas das Haus verlässt — im JSON wie in den Bild-Endpunkten.

Das Overlay-Prinzip

MPD legt sich über die Foto-Ordner. Es schreibt eine album.json und kleine Zwischenspeicher mit führendem Punkt daneben; die Originale bleiben unberührt. Genau eine Stelle weicht davon ab: der Foto-Editor schreibt Pixel zurück — mit einer Sicherungskette aus fünf Ständen (.bak … .bak4).

Three promises that shape everything

Knowing them explains why some features are missing on purpose.

stays yours

Your photos stay yours.

No cloud, no third-party account. An album is a folder with an album.json in the open PDX format. Delete MPD tomorrow and you keep your photos and readable albums.

share by giving

Sharing means giving.

Two ways, neither of them a feed: a share link from the server (recipients see an album to look at — no likes, no comments, no counter) and plain handing a photo to another app through Android's share sheet.

locked = mine

Private stays private.

The server filters locked elements out of a share before anything leaves the house — in the JSON and in the image endpoints alike.

The overlay principle

MPD lays itself over the photo folders. It writes an album.json and small dot-prefixed caches next to them; the originals stay untouched. Exactly one place differs: the photo editor writes pixels back — with a backup chain of five versions (.bak … .bak4).

2. Schnellstart2. Quick start

2.1 Installieren2.1 Install

Zwei Wege, dasselbe Image:

  • Synology-Paket (.spk, DSM 7, braucht den Container Manager): Paket-Zentrum → Manuelle Installation. Ein Assistent fragt Foto-Freigabe, Port und Konten ab. Daten liegen unter /volume1/docker/MPD/data.
  • Docker Compose auf jedem Linux-Rechner: drei Ordner (photos, homes, data), eine mpd.env, dann docker compose up -d --build. Die README beschreibt die Schritte.

MPD lauscht auf Port 8089. Für den Zugriff von außen gehört es hinter einen Reverse Proxy (z. B. den von DSM) — und MPD_BASE_URL in die mpd.env, damit geteilte Links auf die richtige Adresse zeigen.

Two ways, the same image:

  • Synology package (.spk, DSM 7, needs Container Manager): Package Center → Manual Install. A wizard asks for the photo share, port and accounts. Data lives under /volume1/docker/MPD/data.
  • Docker Compose on any Linux machine: three folders (photos, homes, data), an mpd.env, then docker compose up -d --build. The README lists the steps.

MPD listens on port 8089. For access from outside, put it behind a reverse proxy (e.g. DSM's) — and set MPD_BASE_URL in mpd.env so shared links point to the right address.

2.2 mpd.env2.2 mpd.env

Eine flache Datei, gelesen von backend/config.py beim Start — keine Umgebungsvariablen, kein python-dotenv. Ein Tippfehler im Schlüssel fällt nicht auf: dann gilt still die Vorgabe. Alle Schalter mit Vorgabe und Erklärung stehen in mpd.env.example; im Paket erzeugt der Container die Datei bei jedem Start neu, eigene Zeilen gehören nach /data/mpd.env.local.

Mehrere Einstellungen gibt es zusätzlich im Einstellungsdialog (Admin): SMTP, Formulierungshilfe, Teilen an/aus. Dort Gesetztes gewinnt, mpd.env ist der Rückfall.

One flat file, read by backend/config.py at start — no environment variables, no python-dotenv. A typo in a key goes unnoticed: the default silently applies. All options with defaults and explanations are in mpd.env.example; in the package the container regenerates the file on every start, your own lines go into /data/mpd.env.local.

Several settings also exist in the settings dialog (admin): SMTP, writing assistant, sharing on/off. What is set there wins; mpd.env is the fallback.

3. Architektur3. Architecture

Eine FastAPI-App, eine Auth-Middleware vorn, Router dahinter, Fachlogik in core/. Kein ORM, keine Datenbank für Inhalte, kein Frontend-Build. Das ist Absicht: Fast alles lässt sich mit ls, cat und einem Texteditor nachvollziehen.

One FastAPI app, one auth middleware in front, routers behind it, business logic in core/. No ORM, no database for content, no frontend build. On purpose: almost everything can be followed with ls, cat and a text editor.

3.1 Ein Request3.1 A request

Jeder Request läuft erst durch die Auth-Middleware (Public-Pfade durchgewinkt, alles andere session-pflichtig), dann zum passenden Router. Side-helpers wie i18n, ratelimit, sessiondb werden aus beiden Schichten gerufen.Every request hits the auth middleware first (public paths waved through, everything else session-gated), then routes to the matching router. Side helpers like i18n, ratelimit, sessiondb are called from both layers.

  • Öffentlich sind nur die Pfade in _PUBLIC_PATHS und _PUBLIC_PREFIXES in main.py — Anmeldung, statische Dateien, /share/… und /contrib/… (beide ratenbegrenzt), /api/version. Jeder Eintrag dort ist eine Sicherheitsentscheidung.
  • Alles andere braucht eine gültige Sitzung (Cookie oder Bearer-Token). Demo-Sitzungen dürfen nur GET/HEAD; ist must_change_password gesetzt, bleibt nur der Passwortwechsel offen.
  • Im Router prüfen require_session() und die Funktionen aus routers/deps.py — die eine Datei mit dem ganzen Rechtemodell. Pfade entstehen ausschließlich über get_path()/get_api(), nie durch Zusammensetzen.
  • Public are only the paths in _PUBLIC_PATHS and _PUBLIC_PREFIXES in main.py — sign-in, static files, /share/… and /contrib/… (both rate-limited), /api/version. Every entry there is a security decision.
  • Everything else needs a valid session (cookie or bearer token). Demo sessions may only GET/HEAD; with must_change_password set, only the password change stays open.
  • In the router, require_session() and the functions in routers/deps.py check — the one file holding the whole permission model. Paths come only from get_path()/get_api(), never from string joins.

3.2 Anmeldung3.2 Sign-in

  • Passwörter: Argon2id (64 MiB, 3 Durchläufe, 4 Lanes) in users.json, Datei mit 0600, atomar geschrieben. Auch bei unbekanntem Konto wird ein Dummy-Hash geprüft — die Antwortzeit verrät nicht, ob es das Konto gibt.
  • Sitzungen: Token = uuid4().hex; in mpd.sqlite steht nur sein SHA-256. Cookie mpd_session: HttpOnly, SameSite=Lax, Secure unter HTTPS, 30 Tage. Sitzungen überleben einen Neustart.
  • Native App: POST /api/login mit "want_token": true liefert denselben Token zusätzlich im JSON; die App schickt ihn als Authorization: Bearer …. Bearer hat Vorrang vor dem Cookie.
  • Sperre: 5 Fehlversuche in 5 Minuten → 60 Sekunden gesperrt, je IP (core/ratelimit.py). Dieselbe Regel schützt /share/ und /contrib/ vor dem Durchprobieren von Tokens.
  • Demo: /demo-login gibt es nur mit MPD_DEMO=1 und gesetztem MPD_DEMO_PASSWORD; sonst 404. Der Schalter in den Einstellungen kann es nur abschalten — eine Einstellung, die man umlegen kann, darf keine Sicherheitszusage sein.
  • Passwords: Argon2id (64 MiB, 3 iterations, 4 lanes) in users.json, file mode 0600, written atomically. Unknown accounts still verify a dummy hash — response time does not reveal whether an account exists.
  • Sessions: token = uuid4().hex; mpd.sqlite holds only its SHA-256. Cookie mpd_session: HttpOnly, SameSite=Lax, Secure under HTTPS, 30 days. Sessions survive a restart.
  • Native app: POST /api/login with "want_token": true also returns the token in the JSON; the app sends it as Authorization: Bearer …. Bearer wins over the cookie.
  • Lockout: 5 failures in 5 minutes → 60 seconds locked, per IP (core/ratelimit.py). The same rule protects /share/ and /contrib/ against token guessing.
  • Demo: /demo-login only exists with MPD_DEMO=1 and MPD_DEMO_PASSWORD set; otherwise 404. The switch in the settings can only turn it off — a setting you can flip must never be a security promise.

Vorgabe ist ein Trockenlauf, MPD_THUMB_SWEEP=1 löscht. Drei Riegel: fehlt ein Bestand auf der Platte oder ist die Schlüsselmenge leer, wird nicht gekehrt; frisch Geschriebenes hat 7 Tage Schonfrist.

  • Cache key sha1(absolute path + mtime_ns), stored at /data/thumb-cache/{size}/{key[:2]}/{key}.webp. When the mtime changes (photo editor), a new key results — stale images are never served. The same value is the endpoints' ETag; URLs carry it as ?v= and are then immutable for a year.
  • Warming: core/library_warmer.py runs over all albums on every start (threads: MPD_WARMER_THREADS, default 3). With a full cache it finishes in seconds.
  • Clean-up: sweep_thumb_cache() in core/retention.py removes entries whose photo no longer exists — against the set of valid keys, not by age. Default is a dry run; MPD_THUMB_SWEEP=1 deletes. Three latches: if a collection is missing on disk or the key set is empty, nothing is swept; fresh files get 7 days of grace.
  • Trap: core/filesystem_photos.py has a second, older set (JPEG, sm/m/xl = 200/400/1200) under thumb-cache/fs/. Same short names, different values.

3.4 Kern und Module3.4 Core and modules

Der Kern importiert kein Plus-Modul und läuft ohne jede Plus-Datei. Drei Mechanismen halten das zusammen:

  • Router optional: main.py lädt routers/{memories,stats,search,tours,trails}.py mit ImportError-Schutz. Fehlt eine Datei, fehlt nur ihr Endpunkt; das Log sagt „Modul … nicht mitgeliefert“.
  • Ereignisse statt Aufrufe: core/events.py. Der Kern meldet album_changed und photo_meta_changed; ein Modul hängt sich beim eigenen Import mit subscribe() ein. Handler laufen synchron, ein Fehler wird geloggt, nie geworfen — ein kaputtes Modul lässt keinen Album-Save scheitern.
  • Nachtjobs im Kern: core/scheduler.py ist die eine APScheduler-Instanz. Module hängen ihre Jobs mit add_job() an.

Ob ein Konto ein Modul benutzen darf, entscheiden drei Schichten, die alle zustimmen müssen: installiert (installed_modules()), freigeschaltet (modules in users.json; fehlt das Feld: alle) und — nur bei MPD_LICENSE_ENFORCE=1 — lizenziert (core/license.py). Das Web zeigt gesperrte Module mit Schloss und einer Erklärung; /api/version meldet edition: "core", wenn kein Modul liegt.

The core imports no Plus module and runs without any Plus file. Three mechanisms keep it that way:

  • Optional routers: main.py loads routers/{memories,stats,search,tours,trails}.py guarded by ImportError. A missing file only removes its endpoints; the log says “module … not shipped”.
  • Events instead of calls: core/events.py. The core emits album_changed and photo_meta_changed; a module subscribes on its own import with subscribe(). Handlers run synchronously; an error is logged, never raised — a broken module cannot fail an album save.
  • Night jobs in the core: core/scheduler.py is the one APScheduler instance. Modules attach their jobs with add_job().

Whether an account may use a module is decided by three layers that must all agree: installed (installed_modules()), enabled (modules in users.json; missing field: all) and — only with MPD_LICENSE_ENFORCE=1 — licensed (core/license.py). The web shows locked modules with a lock and an explanation; /api/version reports edition: "core" when no module is installed.

3.5 i18n

Frontend und Backend nutzen dasselbe Muster: ein flaches LOCALES-Dict je Sprache, Punkt-Schlüssel, einfache Platzhalter. Kein Build, keine Bibliothek.

  • Frontend frontend/js/i18n.js: window.t(key, vars) und data-i18n-Attribute. Sprache: localStorage → ?lang= → navigator.language. Die Datei ersetzt window.fetch und hängt jedem Request Accept-Language an — deshalb sieht ein Request im Netzwerk-Tab anders aus als im Code.
  • Backend backend/core/i18n.py: t(key, request, vars) liest Accept-Language; ohne Request (Mail aus einem Nachtjob) t_lang(key, lang, vars).
  • Rückfall: gewünschte Sprache → Deutsch → der Schlüssel selbst. Wer im UI album.foo sieht, hat einen Schlüssel vergessen.

Frontend and backend use the same pattern: one flat LOCALES dict per language, dotted keys, simple placeholders. No build, no library.

  • Frontend frontend/js/i18n.js: window.t(key, vars) and data-i18n attributes. Language: localStorage → ?lang= → navigator.language. The file replaces window.fetch and adds Accept-Language to every request — which is why a request looks different in the network tab than in the code.
  • Backend backend/core/i18n.py: t(key, request, vars) reads Accept-Language; without a request (mail from a night job) use t_lang(key, lang, vars).
  • Fallback: requested language → German → the key itself. If you see album.foo in the UI, a key is missing.

4.3 Hochladen und Einsortieren4.3 Upload and filing

Das Kuratier-Modell: Neues landet im Durchlauf — einem Ordner mit nackter Jahreszahl (2026). Ein Album ist Jahreszahl + Name (2026 - Toskana). Durchlauf-Ordner sind nie Album-Kandidaten. Einsortieren verschiebt die Datei ins Album; jede Datei wohnt in genau einem Ordner, weitere Auftritte laufen über source_album.

  • PUT …/file/{filename} — Hochladen, roher Body (die App, Kamera). Nur Foto/Video, max. 2 GB, atomar.
  • POST …/import-file — einsortieren, auch quer über Bestände. Gleiche Bytes = Dublette (Quelle in den Papierkorb), anderer Inhalt = neuer Name _1.
  • POST /api/album/{space}/year-album — „Rest ins Jahresalbum“: alles aus 2026 nach 2026 - das Jahr.
  • DELETE …/file — löscht in den #recycle-Ordner der Freigabe, wenn es einen gibt (bis zwei Ebenen über dem Bestand, bewusst nicht weiter); recycled in der Antwort sagt, was geschah. Aus einem Albumordner nur mit album_context: true; verweist ein anderes Album per source_album darauf: 409.
  • GET …/unassigned-photos — Dateien im Albumordner ohne Element, dazu skipped: was MPD nicht anzeigen kann, nach Endung.

The curation model: new material lands in the inbox ("Durchlauf") — a folder named by a bare year (2026). An album is year + name (2026 - Tuscany). Inbox folders never become album candidates. Filing moves the file into the album; every file lives in exactly one folder, further appearances use source_album.

  • PUT …/file/{filename} — upload, raw body (the app, camera). Photo/video only, max. 2 GB, atomic.
  • POST …/import-file — file into an album, also across collections. Identical bytes = duplicate (source goes to the recycle bin), different content = new name _1.
  • POST /api/album/{space}/year-album — "rest into the year album": everything from 2026 into 2026 - das Jahr.
  • DELETE …/file — moves into the share's #recycle folder when there is one (up to two levels above the collection, deliberately no further); recycled in the response says what happened. From an album folder only with album_context: true; if another album references the file via source_album: 409.
  • GET …/unassigned-photos — files in the album folder without an element, plus skipped: what MPD cannot show, by extension.

  • Textstile: default, info, quote (mit source), note, heading; Markdown-light *kursiv*, **fett** — gespeichert als Rohtext.

  • Text styles: default, info, quote (with source), note, heading; Markdown-light *italic*, **bold** — stored as raw text.
  • IDs exactly four digits, unique; list order = page order. meta needs title, year, thumbnail, created, modified.
  • Trap ALLOWED in update_album: the whitelist of fields per type. A field missing there is silently dropped on save.

7.3 Regeln in einem Satz7.3 Rules in one sentence

  • Atomar schreiben: tmp-Datei + os.replace, Geheimnisse mit 0600.
  • Pfade: nie base / eingabe ohne resolve() + is_relative_to(). Symlink-Sicherheit kommt aus resolve(), nicht aus is_symlink.
  • Rechte ausschließlich über routers/deps.py; nie session.role direkt prüfen.
  • Texte für Menschen immer über i18n, in beiden Sprachen. Code, Kommentare und Log dürfen Englisch oder Deutsch sein, Log-Zeilen mit %s.
  • Frontend: kein alert()/confirm()/prompt() — window.mpdConfirm(). Nach jeder Änderung an JS/CSS die ?v=N im HTML hochsetzen. Globale Funktionen mit Präfix (album…, lb…): Es gibt keinen Namensraum.
  • Kern und Module: Der Kern importiert kein Modul. Braucht er eines, meldet er ein Ereignis.
  • Caches brauchen ein Signal, das zu ihrer Quelle passt (mtime, Ereignis) — Zeit allein ist kein Grund.
  • Write atomically: tmp file + os.replace, secrets with 0600.
  • Paths: never base / input without resolve() + is_relative_to(). Symlink safety comes from resolve(), not from is_symlink.
  • Permissions only through routers/deps.py; never check session.role directly.
  • Text for people always through i18n, in both languages. Code, comments and logs may be English or German, log lines with %s.
  • Frontend: no alert()/confirm()/prompt() — window.mpdConfirm(). After every JS/CSS change raise the ?v=N in the HTML. Global functions get a prefix (album…, lb…): there is no namespace.
  • Core and modules: the core imports no module. If it needs one, it emits an event.
  • Caches need a signal matching their source (mtime, event) — time alone is no reason.
